## 分片磁盘缓存

看过的片段会存到本地，往回拖或重看同一集时不用重新下载。

- 只缓存媒体分片，播放列表和密钥不缓存；上限 400MB，单条超过 16MB 不存
- 7 天未使用自动清理，超出上限按最久未用淘汰
- 命中缓存时按当前带宽估算「这些字节真下要多久」再交给 hls.js，避免它以为网速暴涨而把码率升到撑不住
- 设置页新增「分片缓存」开关，默认开启；关闭后不再读写，已占的空间会立即释放
- 「清除页面缓存」会一并清空这部分数据

**说明**：只对已经下载过的片段有效。拖到没看过的新位置仍然要等网络，这部分靠下面的等缓冲逻辑兜。

## 拖动后先攒够缓冲再播

采集站的 m3u8 常见「下载速度 ≈ 码率」，hls.js 只要拿到第一片就开播，结果很快被抽干，表现为播一秒卡一下。

现在拖动后会先攒够 3 秒缓冲再开始播，最多等 15 秒。中间显示「正在缓冲 x.xs / 3s」。拖动落在已缓冲区间里则不等待，直接播。

## 卡顿自动降档

- 一分钟内卡顿达到 3 次，自动降一档清晰度并提示
- 最多连降 2 档，不会一路降到最低
- 降档是临时的，2 分钟后放开封顶，让 ABR 重新往上试
- 已在最低档时不再提示「已降低清晰度」

## 全屏顶部信息条

全屏播放时顶部显示剧名、集数、当前分辨率、电量和时钟。跟随 ArtPlayer 的控制条一起淡入淡出，不额外接管点击事件。

## 设置页诊断信息

新增「诊断信息」卡片，一键复制当前环境数据，反馈问题时贴出来能直接看出问题。

包含：版本、运行环境、系统、屏幕与窗口尺寸、可视区尺寸与缩放、安全区、方向、页面滚动锁状态，以及上一次播放的片名、集数、进度、播放引擎、前向缓冲、码率档位、带宽估计、近一分钟卡顿与降档次数、缓冲参数。

## 车机 / 大屏继续修复

针对反馈的「点搜索结果弹不出菜单、无法上下滑动、lock 按钮溢出屏幕」：

- 详情弹层改用 `visualViewport` 判断位置，不再依赖 `vh`，车机 WebView 里两者经常对不上
- 遮罩改为贴着真实可见区，不再跟着 layout viewport 走
- 扣掉入场动画的位移再量位置，避免动画起始帧被误判成溢出
- 还有一部分被切在屏外时，退化成顶部对齐的满高面板，保证关闭键和「立即播放」都在屏幕内
- **只有弹层真的落在可见区内才锁页面滚动**。之前锁了却看不见，用户既操作不了弹层也滑不动列表
- 播放器高度扣掉 48px 顶栏和安全区，横屏时底部控制条（含 lock 按钮）不再被切在屏幕外
- 旋转屏幕、软键盘、地址栏收起都会重新校准

## 缓冲参数调整

- `maxBufferHole` 从 0.5 改回 0.1：0.1~0.5 秒的真实空洞以前被当成不存在，既不去补也不触发 nudging，播到那里就停住
- `abrBandWidthUpFactor` 从 0.7 降到 0.6：升档更保守
- 开启 `capLevelToPlayerSize` 和 `capLevelOnFPSDrop`：按播放器尺寸封顶，手机平板上 1080P 和 720P 肉眼几乎没差别，码率却差一倍多
- 手机端缓冲目标从 60 秒 / 120 秒降到 30 秒 / 60 秒：目标缓冲越长，ABR 越敢选高档，结果选到刚好撑不住的码率，播放中反复被抽干

## 修复

- 分片广告过滤会删掉 `#EXT-X-DISCONTINUITY` 整行，导致 hls.js 不知道时间戳要跳变，remuxer 按连续时间戳算分段时长，缓冲区出现空洞或重叠，表现为播到某个位置卡住。现在保持原样返回，等真正按分片内容判断广告的方案
- 关闭「分片广告过滤」时原本会绕过自定义 loader，导致分片缓存一起失效

## 已知限制

- 分片缓存只对下载过的片段有效，首次观看、拖到新位置仍受线路速度限制
- 车机适配只在代码层面修正了布局计算，没有实机验证，仍需反馈
