## 老设备（Chrome 88 以前）播放器没有画面

部分车机、电视盒子的 WebView 内核停在 Chrome 83 左右，播放器区域高度会塌成 0：有声音、没画面，控制条也摸不到（它也在那个 0 高度里）。

原因是播放器容器的高度只靠 CSS `aspect-ratio` 撑，而这个属性 Chrome 88 才有。内核不认这条声明，父容器高度就是 `auto`，里面的百分比高度全部失效，最后只剩一堆绝对定位元素，实际高度 0。

这一版做了两层兜底，**只在不支持 `aspect-ratio` 的内核上生效**：

- CSS 层：`@supports not (aspect-ratio: 16 / 9)` 里给播放器容器补 `height: 56.25vw`
- JS 层：启动时探测能力，不支持就按「容器宽度 × 9/16」和「可用高度」算一个精确值写进内联样式，窗口尺寸变化会重算

现代内核（Chrome 88 及以上）上这两层都不会执行，行为与之前完全一致。

## 同一批老内核的其它兜底

- 封面图（搜索结果、历史、详情页、简介）改用 `::before` 撑 2:3 比例，老内核上不再塌成一条线
- `inset` 简写（Chrome 87 才有）补了四边写法的等价规则，遮罩层、开关圆点、加载层、同步浮层不再错位
- 两处只写了 `dvh` 的高度补了 `vh` 兜底

## 诊断信息新增【兼容性】

```
aspect-ratio：是/否
inset 简写：是/否
dvh 单位：是/否
播放器外壳：宽×高，内联高度
播放器盒子：宽×高
视频元素：宽×高
```

老设备上如果还有问题，这几行能直接看出是布局没算对，还是视频本身没解码。

## 已知限制

- 老内核的兼容改动**没有在真机上验证过**，是按 Chrome 83 的特性缺失推导的
- 老内核上依然没有 `aspect-ratio`，其它页面如果有依赖它的地方（目前排查过，主要是封面，已兜底）
- 投屏功能仍未实现
