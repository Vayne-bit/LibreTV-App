## 广告过滤强化

这一版的广告过滤改动来自社区 PR（感谢 [@htcnokia](https://github.com/htcnokia)）。原来的过滤只认「`#EXT-X-DISCONTINUITY` 分段 + 块很短 + 域名不一样」这一种结构，很多源识别不出来。这版在原有结构判断之前加了两道：

- **主机特征法**：播放列表里的分片地址如果命中已知广告域名（约 27 个常见广告/追踪域）或路径里带 `/ads/`、`/preroll/`、`/interstitial/` 这类片段，直接删掉
- **学习型黑名单**：某次过滤里被确认是广告的域名会记到本地（最多 64 个），下次遇到同域名分片直接当广告；正片里出现过的域名不会被记
- **`#EXT-X-DATERANGE` 标记**：支持按 SCTE35 广告标记剔除对应分段
- **放宽块长上限**：单个广告块允许的最大时长从 180 秒提到 300 秒

## 安全修复

- **XSS**：搜索结果卡片、剧集按钮原来是拼接 HTML 字符串，转义写成了 `replace(/</g, '<')`——替换成它自己，等于没转义。改为通过 `data-*` 属性取数据，不再拼进 HTML
- **代理 SSRF**：内置代理的地址校验补上私网拦截（`127.`、`10.`、`192.168.`、`169.254.`、`172.16–31.`、`::1`、`fc/fd`、`fe80:`、`.local`、`.internal` 等）
- **调试日志**：原来会把请求明文写进 `proxy_debug.log` 并随仓库提交。现在默认不写，需要时设 `PROXY_DEBUG=1` 才开；仓库里那份历史日志已删除

## hls.js 升级到 1.7.4

播放内核从 1.6.2 升到 1.7.4，官方 dist 原样替换，没有改任何调用代码。

1.7 是一个较大的版本，但主要新能力（I-frame 播放、CMCD、DRM、低延迟 HLS）我们用不到，实际能感受到的是 1.7.1 到 1.7.4 的 bug 修复：分片加载重试、initPTS 对齐、部分 `fMP4`/`WebVTT` 场景的兼容问题，以及 1.7.4 修掉了 1.7.0 自己引入的「parameter set 截断」回归。官方声明 1.6 → 1.7 不需要改运行时代码。

## 投屏（本版未包含）

DLNA / Chromecast / AirPlay 这条线**没有合进本版本**，代码单独放在分支 `feature/dlna-cast`，需要时再单独推进。暂时不合并的原因主要是风险还没收敛：

- Rust 侧 DLNA 实现（SSDP 发现、SOAP 控制、内置流代理）只在个别设备（三星 Tizen、乐播）上有反馈，未做广泛实机验证
- 内置流代理转发时不校验目标地址是否为私网，理论上存在被利用访问内网的风险
- Android 端只为 SSDP 申请了多播锁，没有释放时机
- Chromecast 依赖 `gstatic.com` 的 sender 脚本，国内网络基本不可用；AirPlay 只在非 Android WebView 环境生效

## 已知限制

- 广告过滤仍有两类源处理不了：广告和正片压进**同一个 `.ts` 分片**（切不开）、播放列表里**既没有 `#EXT-X-DISCONTINUITY` 也没有广告标记**的源
- 过滤有兜底：一次要删的时长超过总时长 30% 时会整体放弃，避免误删正片。代价是某些「广告占比很高」的源会一个都不删
- 播放列表只有两个分段（正片 + 片尾广告）时，片头贴片广告的识别可能误判；有 30% 兜底，表现为「不删广告」，不会删坏正片
- hls.js 1.7 线较新，正常播放/切集/倍速/长时间挂机建议实机再验一遍
